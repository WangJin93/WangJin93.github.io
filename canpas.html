CanPAS - Cancer Prognosis Analysis Suite

A curated cross-archive resource and R toolkit for survival analysis of public cancer cohorts.

📦 Version: 1.0.0 👤 Author: Jin Wang 📧 Maintainer: jin.wang93@outlook.com 📅 Date: 2026-09-26

1. Introduction

CanPAS (Cancer Prognosis Analysis Suite) is an R package and a curated data resource for survival analysis of public cancer cohorts. It serves expression matrices and harmonised survival tables from a curated GEO / EMBL-EBI / TCGA / CGGA / cBioPortal-hosted mirror over a public REST API, and from TCGA through UCSC Xena with local clinical tables, exposing one uniform "merged data" schema.

Endpoints are requested by family (OS, DSS, DFS, PFS, MFS), and the token a cohort actually reports is resolved per cohort and returned with every result, so cohorts are never pooled across families. Functions cover gene and signature scoring, Kaplan-Meier and cut-point analysis, univariable and multivariable Cox models, time-dependent ROC, cross-cohort random-effects meta-analysis, pooled Kaplan-Meier with a prediction interval, and competing risks, with five statistical safeguards disclosed by default. A bundled Shiny application drives the same exported functions.

Features

  • 197 curated cohorts, 29 cancer types and 38,981 analysable samples behind one uniform schema
  • Endpoint-family harmonisation: RFS/DFI/EFS pooled as DFS, PFI as PFS, DRFS as MFS, CSS/BCSS as DSS
  • Expression table + harmonised survival table per cohort (time in years, status 0/1), plus clinical covariates where available
  • Gene and weighted signature scoring, Kaplan-Meier and cut-point analysis
  • Univariable / multivariable Cox models, panel screening and cross-dataset Cox
  • Time-dependent ROC, cross-cohort random-effects meta-analysis and pooled Kaplan-Meier
  • Competing-risks Cox models and cumulative incidence curves
  • Bundled Shiny application covering the same exported functions

4. Function Reference

4.1 get_data

Description

Query the CanPAS public API (backed by a MySQL mirror of GEO series-matrix survival / expression tables). The response is returned as a structured object of class cpas_get together with the exact URL used.

Usage

get_data(
  dataset,
  action = c("expression", "gpl", "surv_data"),
  ids = NULL,
  base_url = "https://www.jingege.wang/bioinformatics/CPAS/api.php",
  timeout_sec = 120,
  use_cache = NULL
)

Arguments

ArgumentDescription
datasetMirror table to query: a dataset accession for action = "expression" / "surv_data", or a platform id (e.g. "GPL96") for action = "gpl". The value is sent to the API as its table request parameter, with a dash sent as the underscore the mirror uses ("A5-PCPG" queries the table A5_PCPG).
actionOne of "expression" (sample-level expression of the requested probes/ids), "gpl" (probe-to-gene mapping of a platform) or "surv_data" (survival table of a dataset).
idsReference ids (probes for action = "expression", Entrez gene ids for action = "gpl"). Ignored for action = "surv_data". May be a character vector; multiple ids are collapsed with ",".
base_urlAPI endpoint. Defaults to the CanPAS public API.
timeout_secConnection timeout in seconds passed to getOption("timeout") for the duration of the call.
use_cacheReuse the local file cache. NULL (default) follows getOption("CanPAS.cache", TRUE) and the environment variables CANPAS_CACHE / CPAS_CACHE; TRUE or FALSE forces the choice for this call. Cached answers are used even after expiry when the network request fails.

Examples

## The mirrored survival table of a real cohort (ID, endpoint columns
## and clinical covariates).
r <- get_data(dataset = "GSE31210", action = "surv_data")
head(r$response)

## Sample-level expression for chosen platform ids.
e <- get_data(dataset = "GSE14814", action = "expression",
              ids = c("1053_at", "200801_x_at"))
head(e$response)[, 1:4]
4.2 get_expr_data

Description

Resolves gene symbols to probes on the dataset's platform (via the ID_map table and the platform's probe-to-gene mapping) and downloads the matching expression values from the CanPAS API. Multiple probes mapping to the same gene can be collapsed with a user-selected rule. Datasets whose accession starts with "TCGA-" are handled differently: values are fetched per gene from UCSC Xena on demand, so there is no probe resolution and process_duplicates is ignored.

Usage

get_expr_data(
  dataset,
  gene = NULL,
  process_duplicates = c("max", "mean", "median", "min", "no"),
  genes = NULL
)

Arguments

ArgumentDescription
datasetDataset accession in dataset_info, e.g. "GSE14814" or "TCGA-LUAD".
geneCharacter vector of gene symbols.
process_duplicatesHow to collapse several probes that map to the same gene: "max" (default), "mean", "median", "min" - or "no" to keep probe-level rows (columns then carry probe ids instead of symbols). Ignored for TCGA datasets.
genesOne or more gene symbols (character); equivalent to gene (supply only one of the two).

Examples

## GEO: probe ids are resolved through the platform map and collapsed
## to one value per gene.
e <- get_expr_data(dataset = "GSE31210", genes = c("FOXM1", "TP53"))
e$metadata
head(e$expr_data)

## TCGA: values are fetched per gene from UCSC Xena (gene-level log2).
tcga <- get_expr_data(dataset = "TCGA-LUAD", genes = "TP53")
head(tcga$expr_data)
4.3 merge_surv_expr

Description

Pulls the survival table of a dataset from the CanPAS API and joins it with gene expression data produced by get_expr_data() on the common sample identifier (ID). For datasets whose accession starts with "TCGA-" the local TCGA clinical table is used instead of the mirror.

Usage

merge_surv_expr(dataset, expr_data)

Arguments

ArgumentDescription
datasetDataset accession in dataset_info (e.g. "GSE14814" or "TCGA-LUAD").
expr_dataResult object of class cpas_get_expr returned by get_expr_data() (an object with an expr_data element whose first column is ID) or a plain data.frame in that format.

Examples

e <- get_expr_data(dataset = "GSE31210", genes = c("FOXM1", "TP53"))
m <- merge_surv_expr(dataset = "GSE31210", expr_data = e)

## merged_data: ID, <TYPE>_time (years), <TYPE>_status (0/1), gene columns
colnames(m$merged_data)

## raw_surv_data keeps the clinical columns of that cohort.
colnames(m$raw_surv_data)
4.4 endpoint_resolve

Description

Returns the concrete endpoint token available for a cohort and endpoint (family name or raw token), using the columns of the packaged dataset_info catalog (e.g. EP_DFS). A family is resolved to the token the cohort actually provides; a raw token is returned only when it is a known endpoint token, otherwise NA.

Usage

endpoint_resolve(dataset, type)

Arguments

ArgumentDescription
datasetDataset accession (e.g. "GSE31210", "TCGA-LGG").
typeFamily name ("OS", "DSS", "DFS", "PFS", "MFS") or a raw endpoint token.

Examples

## The token a real cohort actually contributes for a family.
endpoint_resolve("GSE31210", "DFS")    # "RFS": that cohort is RFS-based
endpoint_resolve("GSE13507", "OS")     # "OS"
endpoint_resolve("TCGA-LUAD", "PFS")   # "PFI"

## NA is returned when the cohort has no endpoint of that family.
endpoint_resolve("GSE31210", "DSS")
endpoint_resolve("E-MTAB-1205", "DFS") # "DFS"
4.5 endpoint_options

Description

Returns one row per endpoint family available for a cohort, with the concrete endpoint token, whether the token is a TCGA-derived endpoint, the analysis family and a display label such as "DFS (RFS)" or "DFS (DFI) [derived]".

Usage

endpoint_options(dataset, family = NULL)

Arguments

ArgumentDescription
datasetDataset accession (e.g. "GSE31210", "TCGA-LGG").
familyOptional family filter (one or more of "OS", "DSS", "DFS", "PFS", "MFS").

Examples

## What a real cohort can be analysed on, with the token per family.
endpoint_options("TCGA-LGG")
endpoint_options("GSE13507")

## Only one family at a time, when that is all you need.
endpoint_options("GSE31210", family = "DFS")
4.6 COX_by_genes

Description

Fits one univariable Cox proportional-hazards model per gene (Surv(time, status) ~ gene) and returns hazard ratios, 95% confidence intervals, Wald p-values and Benjamini-Hochberg FDRs for every gene, together with the fitted model objects. This is a panel screen: each gene is estimated separately and the genes are never adjusted for one another.

Usage

COX_by_genes(df, type = "OS", genes)

Arguments

ArgumentDescription
dfData.frame whose first column is ID and that contains the columns <type>_time (years), <type>_status (0/1) and one numeric column per marker.
typeEndpoint family ("OS", "DSS", "DFS", "PFS", "MFS") or a concrete token ("RFS", "DFI", "PFI" ...). Families are resolved to the token available in df.
genesCharacter vector of gene (expression) columns to test.

Examples

d <- cohort_merged("GSE31210", c("FOXM1", "TP53"), type = "OS")
r <- COX_by_genes(d, type = "OS", genes = c("FOXM1", "TP53"))

## gene, HR, HR95L, HR95H, Pvalue, P_adj (BH-FDR across the panel)
head(r$results_table)
4.7 COX_analysis

Description

Fits Cox proportional-hazards models on a data.frame of survival plus continuous and/or categorical covariates, and formats a tidy results table (hazard ratios, 95% CIs, Wald p-values, sample sizes per variable). Use method = "uni" for one model per covariate and method = "multi" for a single multivariable model with all covariates.

Usage

COX_analysis(
  df,
  type = NULL,
  cont_Variates = NULL,
  cate_Variates = NULL,
  method = c("uni", "multi"),
  precision = 3,
  min_level_n = 5L,
  min_covariates = 2L,
  drop_nonestimable = TRUE
)

Arguments

ArgumentDescription
dfData.frame. If type is given it must contain ID, <type>_time and <type>_status; if type = NULL the columns must already be named time and status.
typeEndpoint family (OS/DSS/DFS/PFS/MFS) or concrete token; the family is resolved to the token available in df. NULL when df already contains time/status. Default NULL.
cont_VariatesCharacter vector of continuous covariate columns.
cate_VariatesCharacter vector of categorical covariate columns (the first factor level is the reference level).
methodEither "uni" (one model per covariate) or "multi" (single multivariable model with all covariates).
precisionDecimal places used to format the display columns (HR_text, P_text); numeric columns keep full precision.
min_level_nInteger. Minimum number of patients required for a categorical level to keep its own coefficient in the multivariable model. Rarer levels are merged into an "Other" level when that leaves the covariate usable. Default 5.
min_covariatesInteger. Number of covariates below which the multivariable model is no longer regarded as an adjusted model; metadata$reduced is then TRUE. Default 2.
drop_nonestimableLogical. If TRUE (default) a non-estimable multivariable model is repaired instead of being refused: non-estimable covariates are located and removed one at a time, and every decision is reported in metadata$dropped_covariates and metadata$drop_notes. If FALSE the model is fitted on the raw complete cases and an error is raised when it is not estimable.

Examples

## Prerequisite chain: expression plus survival, with clinical covariates.
d <- cohort_merged("GSE13507", c("FOXM1", "TP53"), type = "OS", clin = TRUE)

## One model per covariate.
r <- COX_analysis(d, type = "OS", cont_Variates = c("FOXM1", "age"),
                   cate_Variates = c("grade", "N"), method = "uni")
head(r$results_table)

## Joint model, with every covariate removal recorded and explained.
r2 <- COX_analysis(d, type = "OS", cont_Variates = c("FOXM1", "age"),
                    cate_Variates = c("grade", "N"), method = "multi")
r2$metadata$dropped_covariates
r2$metadata$reduced

Description

One-stop helper: retrieves expression of the requested genes for a dataset, merges it with the survival table, and draws a grid of Kaplan-Meier plots (median split) for every gene that maps on the platform.

Usage

quick_km(
  dataset,
  genes,
  process_duplicates = "max",
  type = "OS",
  ncol = 3,
  cutpoint = "median",
  ...
)

Arguments

ArgumentDescription
datasetDataset accession in dataset_info (GEO), or "TCGA-<PROJECT>" (e.g. "TCGA-LUAD").
genesCharacter vector of gene symbols.
process_duplicatesCollapsing rule for multiple probes per gene (see get_expr_data()). Default "max".
typeEndpoint family (OS/DSS/DFS/PFS/MFS) or concrete token. A family is resolved to the token available in the cohort (e.g. DFS -> RFS/DFI/EFS).

4.9 get_signature_value

Description

Parses a linear signature string such as "0.3*GAPDH + 0.7*ACTB + 0.5*RPN1" and computes the weighted sum of expression values for every sample of a dataset. Weights are applied in the order of the signature string.

Usage

get_signature_value(
  signature,
  dataset,
  process_duplicates = "max",
  allow_missing = FALSE
)

Arguments

ArgumentDescription
signatureCharacter string of the form <weight>*<GENE> +/- <weight>*<GENE> ... (weights may be negative).
datasetDataset accession (GEO or "TCGA-<PROJECT>").
process_duplicatesProbe collapsing rule passed to get_expr_data() (default "max").
allow_missingIf FALSE (default), all signature genes must be measurable on the platform; otherwise the score is computed on the subset of genes that are available (with a message).

Examples

s <- get_signature_value(signature = "0.5*FOXM1 + 0.5*TP53",
                         dataset = "GSE31210")
s$metadata$genes_used; s$metadata$sample_count
s$signature_info$weights   # the parsed weights, in order
head(s$results_table)      # ID + one score per patient

## Genes that are not measurable in that cohort: score the available subset.
s2 <- get_signature_value("0.5*FOXM1 + 0.5*TP53", "GSE31210",
                          allow_missing = TRUE)
s2$metadata$genes_missing
4.10 cpas_meta

Description

Two-stage cross-cohort meta-analysis on cohorts of the same cancer type: stage 1 fits coxph(Surv(time, status) ~ marker) in every cohort to obtain logHR and SE; stage 2 pools them by inverse-variance weighting (fixed effect, or random effects with DerSimonian-Laird) and reports the pooled HR (95% CI), Z/p and the heterogeneity statistics Q/df/I²/tau².

Usage

cpas_meta(
  datasets,
  marker,
  type = "OS",
  method = c("RE", "FE"),
  confounders = NULL,
  min_events = 5,
  max_try = 3,
  merged = NULL
)

Arguments

ArgumentDescription
datasetsCharacter vector of dataset accessions (matching dataset_info$Accession).
markerA single gene symbol (e.g. "FOXM1") or a signature formula string (e.g. "0.5*FOXM1+0.3*TP53").
typeEndpoint family (OS/DSS/DFS/PFS/MFS) or raw endpoint token (OS/DSS/DFS/RFS/PFS/MFS/DFI/PFI/DRFS/EFS ...). The family is resolved to the concrete token per cohort (see endpoint_resolve()) and recorded in per_dataset$endpoint.
method"RE" (random effects, default) or "FE" (fixed effect).
confoundersOptional character vector of multivariable-adjustment covariate names (must exist in the merged data; the per-cohort intersection of available covariates is used).
min_eventsMinimum number of events for a cohort to be included (default 5).
max_tryNumber of retries when data retrieval fails for a cohort (to absorb API jitter).
mergedOptional named list (cohort name -> already merged data.frame). When supplied, no network retrieval is performed.

Examples

## Two lung-cancer cohorts, one OS analysis.
m <- cpas_meta(c("TCGA-LUAD", "GSE31210"), marker = "FOXM1", type = "OS")
m$per_dataset[, c("dataset", "endpoint", "n", "events", "HR")]
m$pooled              # pooled HR (95% CI), Z/p, Q/df/I2/tau2

loo_meta(m)           # leave-one-out sensitivity
print(m)
4.11 plot_meta_forest

Description

Draws the forest plot of a cpas_meta() result: the per-cohort HR (95% CI) and the pooled HR. Per-cohort significance stars and the pooled HR / 95% PI annotation are anchored inside the panel, so they are never silently dropped.

Usage

plot_meta_forest(
  x,
  digits = 4,
  show_stars = TRUE,
  label_size = 4.2,
  star_size = NULL,
  y_headroom = 3.6,
  x_frac = 0.02,
  label_lift = 1,
  label_where = c("inside", "subtitle"),
  ...
)

Arguments

ArgumentDescription
xA cpas_meta object.
digitsDecimal places for the annotations in the figure (default 4).
show_starsWhether to draw per-cohort significance stars at the left edge of the panel (* p<0.05, ** p<0.01, *** p<0.001). Default TRUE.
label_sizeFont size of the pooled HR / 95% PI annotation (default 4.2).
star_sizeFont size of the stars and the Overall label; default 0.85 * label_size.
y_headroomHeadroom at the top of the y axis so that the Overall diamond and its CI are not clipped (default 3.6).
x_fracHorizontal position, as a fraction of the panel width, anchoring the stars and the pooled annotation (default 0.02).

Examples

m <- cpas_meta(c("TCGA-LUAD", "GSE31210"), marker = "FOXM1", type = "OS")
plot_meta_forest(m)
plot_meta_forest(m, digits = 3, label_where = "subtitle")
4.12 cpas_km_pooled

Description

Splits each cohort into High/Low at its own median marker value and then pools by method: "ipd" merges the patients directly for a pooled survfit (the log-rank p is given both pooled and stratified by cohort); "meta" is a two-stage route that pools the per-time-point survival probabilities S(t) of each cohort KM curve on the log(-log S) scale by inverse-variance weighting (RE/FE), giving a pooled survival curve and a 1/3/5-year table; "both" returns the two.

Usage

cpas_km_pooled(
  merged,
  marker,
  type = "OS",
  method = c("both", "ipd", "meta"),
  landmarks = c(1, 3, 5),
  meta_method = "RE",
  cut = c("median", "top_pct", "custom"),
  top_pct = NULL,
  cut_value = NULL
)

Arguments

ArgumentDescription
mergedNamed list of per-cohort merged data.frames from merge_surv_expr(); names must be catalog accessions so that the family is resolved to a concrete endpoint per cohort. The returned object carries dataset_endpoints (the endpoint actually used in each dataset).
markerGene column name.
typeEndpoint (OS/RFS/...); a family is resolved per cohort.
method"ipd", "meta" or "both".
landmarksLandmark time points (in years) to report.
meta_methodRE = random effects (DerSimonian-Laird, default), FE = fixed effect, for the time-point pooling.
cutHigh/Low grouping rule: "median" (default, High = marker above that cohort's own median), "top_pct" (High = the top top_pct% of that cohort by expression) or "custom" (absolute threshold cut_value on the log2 scale or signature score).
top_pctPercentage for cut = "top_pct": a single finite value between 1 and 99. The threshold uses stats::quantile() (type 7); cohorts left with an empty side are recorded in empty_cohorts with a reason and do not enter the pooling.
cut_valueThreshold for cut = "custom": a single finite value applied to log2 expression (or signature score). Cohorts with no patient on one side of it are recorded in empty_cohorts and excluded.

Examples

## Explicitly built list of merged cohorts (names must be accessions).
merged <- list(GSE31210 = cohort_merged("GSE31210", "FOXM1", type = "RFS"),
               GSE37745 = cohort_merged("GSE37745", "FOXM1", type = "RFS"))

km <- cpas_km_pooled(merged, marker = "FOXM1", type = "RFS", method = "both")
km$datasets; km$dataset_endpoints; km$logrank_p
km$skipped_cohorts; km$skipped_reasons

plot_cpas_km(km)                       # pooled curve + landmark table
plot_cpas_km_perdataset(km, ncol = 2)  # one panel per cohort

5. Shiny Application

The Shiny application is bundled with the package and is started locally with run_cpas_app(). There is no hosted instance: the app is served from your own R session, and the analysis pages query the CanPAS public API at run time.

The application has the following pages:

  • Dashboard - an overview of the resource and the catalog.
  • Datasets - single-dataset analysis, Kaplan-Meier, Cox regression, Cox by genes, multi-datasets analysis, Cox by datasets, pooled Kaplan-Meier and meta-analysis.
  • Methods - the statistical conventions the functions follow.
  • Help - page-by-page documentation of the app.
library(CanPAS)
run_cpas_app()                 # free port, opens the browser
run_cpas_app(port = 3838)      # fixed port

6. Data Sources & API

CanPAS is built on a curated catalog of 197 cohorts covering 29 cancer types and 38,981 analysable samples, assembled from five source archives:

Source archiveCohorts
GEO145
EMBL-EBI14
TCGA33
CGGA3
cBioPortal-hosted2

Cohort-by-family coverage is OS 142, DSS 41, DFS 98, PFS 49 and MFS 17. Every delivered cohort comes with an expression table and a harmonised survival table (time in years, status 0/1), plus clinical covariates where available. TCGA cohorts are the exception on the expression side: the mirror holds no TCGA expression table, so TCGA expression is fetched on demand from UCSC Xena, with the clinical tables held locally.

Non-TCGA cohorts are served from the public data API / mirror at https://www.jingege.wang/bioinformatics/CPAS/api.php, which the package queries through get_data(). The API is rate-limited and answers repeated queries from the local file cache by default.

Endpoint tokens are harmonised to pooling families: RFS, DFI and EFS are treated as DFS, PFI as PFS, DRFS as MFS, and CSS / BCSS as DSS, so cohorts that report different tokens can be pooled within a family.

7. Verification & Reproducibility

The catalog is produced by a scripted curation pipeline of 50+ numbered curation scripts, from series parsing through survival-table construction, clinical standardisation and expression-scale harmonisation. Each step is numbered and rerunnable, so a cohort can be rebuilt from its source series rather than edited by hand.

A verification script cross-checks every catalogued cohort against the data mirror. At the released 197-cohort state it runs 15 checks and reports 0 errors / 0 warnings, with every catalogued row fully usable.

A reproducibility bundle of the curation scripts and a frozen catalog accompany the release, so the delivered cohort tables can be regenerated and the reported counts re-derived.
