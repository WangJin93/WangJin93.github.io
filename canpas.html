CanPAS - Cancer Prognosis Analysis Suite

A curated cross-archive resource and R toolkit for survival analysis of public cancer cohorts.

📦 Version: 1.0.0 ⚖️ Licence: MIT 👤 Author: Jin Wang 📧 Maintainer: jin.wang93@outlook.com 📅 Date: 2026-09-30
📖 Full documentation: https://wangjin93.github.io/CanPAS/

The dedicated pkgdown site is the reference for this package: a reference page for every exported function, plus two articles - Getting started and Endpoints and pooling. It is generated from the released source, so it matches version 1.0.0. Everything below is the short version.

Install the tagged release: remotes::install_github("WangJin93/CanPAS@v1.0.0")

1. Introduction

CanPAS (Cancer Prognosis Analysis Suite) is an R package and a curated data resource for survival analysis of public cancer cohorts. It serves expression matrices and harmonised survival tables from a curated GEO / EMBL-EBI ArrayExpress / TCGA / CGGA / cBioPortal-hosted mirror over a public REST API, and from TCGA through UCSC Xena with local clinical tables, exposing one uniform "merged data" schema.

Endpoints are requested by family (OS, DSS, DFS, PFS, MFS), and the token a cohort actually reports is resolved per cohort and returned with every result, so cohorts are never pooled across families. Functions cover gene and signature scoring, Kaplan-Meier and cut-point analysis, univariable and multivariable Cox models, time-dependent ROC, cross-cohort random-effects meta-analysis, pooled Kaplan-Meier with a prediction interval, and competing risks, with five statistical safeguards disclosed by default. A bundled Shiny application drives the same exported functions.

Version 1.0.0 is the first tagged release (MIT licence, R >= 4.0.0). It is documented on a dedicated site, wangjin93.github.io/CanPAS, with a reference page for every exported function and two articles, 66 man pages and two offline vignettes. Every analysis now also returns an analysis manifest (cpas_manifest()) recording what was analysed and what was changed, and the default behaviour is fail-safe: a model that would need covariates dropped or rows excluded is reported as not estimable with its reasons instead of being silently refitted.

Features

  • 197 curated cohorts across 29 cancer types and 38,981 analysable samples behind one uniform schema, from five source buckets: GEO, EMBL-EBI ArrayExpress/BioStudies, TCGA, CGGA and cBioPortal-hosted studies
  • Endpoint semantics layer: every cohort-by-family cell carries token, token role, event definition, time origin, censoring rule, competing events, source field, derived flag and evidence, plus a pooling class (Exact-equivalent / Clinically-related / Not-poolable / Unknown / Absent) - 347 of the 985 cohort-by-family cells resolved at token level
  • Endpoint-family harmonisation: RFS/DFI/EFS pooled as DFS, PFI as PFS, DRFS as MFS, CSS/BCSS as DSS, with a strict exact-only pooling mode when only the family's own token may be pooled
  • Expression table + harmonised survival table per cohort (time in years, status 0/1), plus clinical covariates where available
  • Gene and weighted signature scoring, Kaplan-Meier and cut-point analysis
  • Univariable / multivariable Cox models, panel screening and cross-dataset Cox
  • Time-dependent ROC, cross-cohort random-effects meta-analysis and pooled Kaplan-Meier
  • Competing-risks Cox models and cumulative incidence curves
  • Fail-safe default: a model that would need covariates dropped or rows excluded returns an explicit "not estimable" result with its reasons instead of silently refitting (auto_repair = TRUE restores the old behaviour and records every change)
  • Defensible statistical defaults: random-effects meta-analysis defaults to REML (DL, Hartung-Knapp and fixed-effect available) with prediction intervals parameterised t / normal / HK; a search-adjusted cut-point p-value; an events-per-variable guard; and a proportional-hazards check
  • Analysis manifest with every result (cpas_manifest()): cohorts, endpoint family and resolved token, pooling classes pooled, selection rule, rows/covariates dropped and why, cut-point rule and number of cut-points searched, PH test, meta method, tau², I², prediction intervals and versions
  • Overlap-aware pooling (cohort_overlap(): warn / refuse / dedupe) for cohorts that share patients, and batch diagnostics (batch_diagnostics(), plot_batch_diagnostics()) documenting why pooling works on within-cohort standardised effect sizes and within-cohort percentile cut-points, so absolute cross-platform differences do not enter the pooled estimate
  • Reproducibility index (cpas_reproducibility_index(), cpas_pipeline_steps()) over the curation steps and the deposited material; the curation pipeline itself ships inside the package as nine consolidated script files under inst/pipeline/
  • Endpoint adjudication tooling (endpoint_adjudication() blinded rating sheets, endpoint_agreement() Cohen's kappa / agreement / adjudication rate)
  • Documentation: a dedicated documentation site, 66 man pages (English), two offline vignettes, citation("CanPAS") and a public issue tracker
  • Bundled Shiny application covering the same exported functions

Because the token a cohort actually reports is mapped to its pooling family, cohorts that report different tokens can be pooled within a family: a cohort contributing RFS and a cohort contributing DFI both enter a DFS analysis, while OS, DSS, DFS, PFS and MFS are never mixed.

Token-level resolution is recorded for 347 of the 985 cohort-by-family cells (197 cohorts x five families), each with its semantic record and its pooling class; the remaining cells are families the cohort simply does not report. Because the class of every cell is known, pooling can run in the documented pooling = "family" mode (Exact-equivalent + Clinically-related, which is what makes a cross-token DFS pool possible) or be restricted to pooling = "exact" (Exact-equivalent cells only).

2. Installation

CanPAS 1.0.0 is an MIT-licensed R package (R >= 4.0.0) with a bundled Shiny app. R CMD check reports 0 errors, 0 warnings and 1 host note. Install the tagged release from GitHub: 

# install the tagged 1.0.0 release (recommended)
remotes::install_github("WangJin93/CanPAS@v1.0.0")

Or install the release tarball attached to the v1.0.0 GitHub release:

install.packages("CanPAS_1.0.0.tar.gz", repos = NULL, type = "source")

To follow the development branch instead of the pinned tag:

remotes::install_github("WangJin93/CanPAS")

All imported packages are on CRAN. Optional packages enable extra features: the Shiny app needs shiny, bs4Dash and DT; TCGA expression through UCSC Xena needs UCSCXenaTools; the search-adjusted cut-point p-value needs maxstat; composing both pooling routes into one figure needs patchwork.

To run the Shiny application shipped with the package:

library(CanPAS)
run_cpas_app()   # free port, opens the browser

Worked examples for both the package and the app are on the documentation site, https://wangjin93.github.io/CanPAS/.

4. Function Reference

4.1 get_data

Description

Query the CanPAS public API (backed by a MySQL mirror of GEO series-matrix survival / expression tables). The response is returned as a structured object of class cpas_get together with the exact URL used.

Usage

get_data(
  dataset,
  action = c("expression", "gpl", "surv_data"),
  ids = NULL,
  base_url = "https://www.jingege.wang/bioinformatics/CPAS/api.php",
  timeout_sec = 120,
  use_cache = NULL
)

Arguments

ArgumentDescription
datasetMirror table to query: a dataset accession for action = "expression" / "surv_data", or a platform id (e.g. "GPL96") for action = "gpl". The value is sent to the API as its table request parameter, with a dash sent as the underscore the mirror uses ("A5-PCPG" queries the table A5_PCPG).
actionOne of "expression" (sample-level expression of the requested probes/ids), "gpl" (probe-to-gene mapping of a platform) or "surv_data" (survival table of a dataset).
idsReference ids (probes for action = "expression", Entrez gene ids for action = "gpl"). Ignored for action = "surv_data". May be a character vector; multiple ids are collapsed with ",".
base_urlAPI endpoint. Defaults to the CanPAS public API.
timeout_secConnection timeout in seconds passed to getOption("timeout") for the duration of the call.
use_cacheReuse the local file cache. NULL (default) follows getOption("CanPAS.cache", TRUE) and the environment variables CANPAS_CACHE / CPAS_CACHE; TRUE or FALSE forces the choice for this call. Cached answers are used even after expiry when the network request fails.

Examples

## The mirrored survival table of a real cohort (ID, endpoint columns
## and clinical covariates).
r <- get_data(dataset = "GSE31210", action = "surv_data")
head(r$response)

## Sample-level expression for chosen platform ids.
e <- get_data(dataset = "GSE14814", action = "expression",
              ids = c("1053_at", "200801_x_at"))
head(e$response)[, 1:4]
4.2 get_expr_data

Description

Resolves gene symbols to probes on the dataset's platform (via the ID_map table and the platform's probe-to-gene mapping) and downloads the matching expression values from the CanPAS API. Multiple probes mapping to the same gene can be collapsed with a user-selected rule. Datasets whose accession starts with "TCGA-" are handled differently: values are fetched per gene from UCSC Xena on demand, so there is no probe resolution and process_duplicates is ignored.

Usage

get_expr_data(
  dataset,
  gene = NULL,
  process_duplicates = c("max", "mean", "median", "min", "no"),
  genes = NULL
)

Arguments

ArgumentDescription
datasetDataset accession in dataset_info, e.g. "GSE14814" or "TCGA-LUAD".
geneCharacter vector of gene symbols.
process_duplicatesHow to collapse several probes that map to the same gene: "max" (default), "mean", "median", "min" - or "no" to keep probe-level rows (columns then carry probe ids instead of symbols). Ignored for TCGA datasets.
genesOne or more gene symbols (character); equivalent to gene (supply only one of the two).

Examples

## GEO: probe ids are resolved through the platform map and collapsed
## to one value per gene.
e <- get_expr_data(dataset = "GSE31210", genes = c("FOXM1", "TP53"))
e$metadata
head(e$expr_data)

## TCGA: values are fetched per gene from UCSC Xena (gene-level log2).
tcga <- get_expr_data(dataset = "TCGA-LUAD", genes = "TP53")
head(tcga$expr_data)
4.3 merge_surv_expr

Description

Pulls the survival table of a dataset from the CanPAS API and joins it with gene expression data produced by get_expr_data() on the common sample identifier (ID). For datasets whose accession starts with "TCGA-" the local TCGA clinical table is used instead of the mirror.

Usage

merge_surv_expr(dataset, expr_data)

Arguments

ArgumentDescription
datasetDataset accession in dataset_info (e.g. "GSE14814" or "TCGA-LUAD").
expr_dataResult object of class cpas_get_expr returned by get_expr_data() (an object with an expr_data element whose first column is ID) or a plain data.frame in that format.

Examples

e <- get_expr_data(dataset = "GSE31210", genes = c("FOXM1", "TP53"))
m <- merge_surv_expr(dataset = "GSE31210", expr_data = e)

## merged_data: ID, <TYPE>_time (years), <TYPE>_status (0/1), gene columns
colnames(m$merged_data)

## raw_surv_data keeps the clinical columns of that cohort.
colnames(m$raw_surv_data)
4.4 endpoint_resolve

Description

Returns the concrete endpoint token available for a cohort and endpoint (family name or raw token), using the columns of the packaged dataset_info catalog (e.g. EP_DFS). A family is resolved to the token the cohort actually provides; a raw token is returned only when it is a known endpoint token, otherwise NA.

Usage

endpoint_resolve(dataset, type)

Arguments

ArgumentDescription
datasetDataset accession (e.g. "GSE31210", "TCGA-LGG").
typeFamily name ("OS", "DSS", "DFS", "PFS", "MFS") or a raw endpoint token.

Examples

## The token a real cohort actually contributes for a family.
endpoint_resolve("GSE31210", "DFS")    # "RFS": that cohort is RFS-based
endpoint_resolve("GSE13507", "OS")     # "OS"
endpoint_resolve("TCGA-LUAD", "PFS")   # "PFI"

## NA is returned when the cohort has no endpoint of that family.
endpoint_resolve("GSE31210", "DSS")
endpoint_resolve("E-MTAB-1205", "DFS") # "DFS"

Usage

endpoint_options(dataset, family = NULL)

Arguments

ArgumentDescription

Examples

4.6 COX_by_genes

Description

Fits one univariable Cox proportional-hazards model per gene (Surv(time, status) ~ gene) and returns hazard ratios, 95% confidence intervals, Wald p-values and Benjamini-Hochberg FDRs for every gene, together with the fitted model objects. This is a panel screen: each gene is estimated separately and the genes are never adjusted for one another.

Usage

COX_by_genes(df, type = "OS", genes)

Arguments

ArgumentDescription
dfData.frame whose first column is ID and that contains the columns <type>_time (years), <type>_status (0/1) and one numeric column per marker.
typeEndpoint family ("OS", "DSS", "DFS", "PFS", "MFS") or a concrete token ("RFS", "DFI", "PFI" ...). Families are resolved to the token available in df.
genesCharacter vector of gene (expression) columns to test.

Examples

d <- cohort_merged("GSE31210", c("FOXM1", "TP53"), type = "OS")
r <- COX_by_genes(d, type = "OS", genes = c("FOXM1", "TP53"))

## gene, HR, HR95L, HR95H, Pvalue, P_adj (BH-FDR across the panel)
head(r$results_table)
4.7 COX_analysis

Description

Fits Cox proportional-hazards models on a data.frame of survival plus continuous and/or categorical covariates, and formats a tidy results table (hazard ratios, 95% CIs, Wald p-values, sample sizes per variable). Use method = "uni" for one model per covariate and method = "multi" for a single multivariable model with all covariates. The multivariable path is fail-safe by default: a model that would have to drop a covariate, merge a rare level or exclude rows is reported as not estimable with its reasons rather than being quietly reduced. Multivariable models warn below 10 events per variable, and the global cox.zph proportional-hazards test is returned with the result (p < 0.05 flagged).

Usage

COX_analysis(
  df,
  type = NULL,
  cont_Variates = NULL,
  cate_Variates = NULL,
  method = c("uni", "multi"),
  precision = 3,
  min_level_n = 5L,
  min_covariates = 2L,
  drop_nonestimable = NULL,
  auto_repair = FALSE
)

Arguments

ArgumentDescription
dfData.frame. If type is given it must contain ID, <type>_time and <type>_status; if type = NULL the columns must already be named time and status.
typeEndpoint family (OS/DSS/DFS/PFS/MFS) or concrete token; the family is resolved to the token available in df. NULL when df already contains time/status. Default NULL.
cont_VariatesCharacter vector of continuous covariate columns.
cate_VariatesCharacter vector of categorical covariate columns (the first factor level is the reference level).
methodEither "uni" (one model per covariate) or "multi" (single multivariable model with all covariates).
precisionDecimal places used to format the display columns (HR_text, P_text); numeric columns keep full precision.
min_level_nInteger. Minimum number of patients required for a categorical level to keep its own coefficient in the multivariable model. Rarer levels are merged into an "Other" level when that leaves the covariate usable. Default 5.
min_covariatesInteger. Number of covariates below which the multivariable model is no longer regarded as an adjusted model; metadata$reduced is then TRUE. Default 2.
drop_nonestimableDeprecated logical, kept for continuity. When supplied it is mapped onto auto_repair; the default is now NULL.
auto_repairLogical, default FALSE (the fail-safe). A model that would have to drop a covariate, merge a rare level or exclude rows is reported as not estimable with its reasons and offending terms in metadata, and no model is returned for it. TRUE restores the previous repairing behaviour - non-estimable covariates are located and removed one at a time - and every decision is recorded.

Examples

## Prerequisite chain: expression plus survival, with clinical covariates.
d <- cohort_merged("GSE13507", c("FOXM1", "TP53"), type = "OS", clin = TRUE)

## One model per covariate.
r <- COX_analysis(d, type = "OS", cont_Variates = c("FOXM1", "age"),
                   cate_Variates = c("grade", "N"), method = "uni")
head(r$results_table)

## Joint model. With the fail-safe default a model that would need a
## covariate dropped is reported as not estimable, with its reasons.
r2 <- COX_analysis(d, type = "OS", cont_Variates = c("FOXM1", "age"),
                    cate_Variates = c("grade", "N"), method = "multi")
r2$metadata$reduced

## auto_repair = TRUE restores the old behaviour and records every change.
r3 <- COX_analysis(d, type = "OS", cont_Variates = c("FOXM1", "age"),
                    cate_Variates = c("grade", "N"), method = "multi",
                    auto_repair = TRUE)
r3$metadata$dropped_covariates

4.9 get_signature_value

Description

Parses a linear signature string such as "0.3*GAPDH + 0.7*ACTB + 0.5*RPN1" and computes the weighted sum of expression values for every sample of a dataset. Weights are applied in the order of the signature string.

Usage

get_signature_value(
  signature,
  dataset,
  process_duplicates = "max",
  allow_missing = FALSE
)

Arguments

ArgumentDescription
signatureCharacter string of the form <weight>*<GENE> +/- <weight>*<GENE> ... (weights may be negative).
datasetDataset accession (GEO or "TCGA-<PROJECT>").
process_duplicatesProbe collapsing rule passed to get_expr_data() (default "max").
allow_missingIf FALSE (default), all signature genes must be measurable on the platform; otherwise the score is computed on the subset of genes that are available (with a message).

Examples

s <- get_signature_value(signature = "0.5*FOXM1 + 0.5*TP53",
                         dataset = "GSE31210")
s$metadata$genes_used; s$metadata$sample_count
s$signature_info$weights   # the parsed weights, in order
head(s$results_table)      # ID + one score per patient

## Genes that are not measurable in that cohort: score the available subset.
s2 <- get_signature_value("0.5*FOXM1 + 0.5*TP53", "GSE31210",
                          allow_missing = TRUE)
s2$metadata$genes_missing
4.10 cpas_meta

Description

Two-stage cross-cohort meta-analysis on cohorts of the same cancer type: stage 1 fits coxph(Surv(time, status) ~ marker + confounders) in every cohort to obtain logHR and SE; stage 2 pools them by inverse-variance weighting and reports the pooled HR (95% CI), Z/p, the heterogeneity statistics Q/df/I²/tau² and a 95% prediction interval for a new cohort. tau² is estimated by REML by default; DerSimonian-Laird, Hartung-Knapp-Sidik-Jonkman and fixed-effect pooling are available, and the alternative prediction interval is always returned beside the one used. A warning names any cohort whose token differs from the family's canonical definition.

Usage

cpas_meta(
  datasets,
  marker,
  type = "OS",
  method = c("REML", "DL", "HK", "FE"),
  pi_method = c("t", "normal", "HK"),
  confounders = NULL,
  min_events = 5,
  max_try = 3,
  merged = NULL,
  pooling = c("family", "exact"),
  overlap = c("warn", "refuse", "dedupe"),
  auto_repair = FALSE,
  class_table = NULL,
  overlap_table = NULL
)

Arguments

ArgumentDescription
datasetsCharacter vector of dataset accessions (matching dataset_info$Accession).
markerA single gene symbol (e.g. "FOXM1") or a signature formula string (e.g. "0.5*FOXM1+0.3*TP53").
typeEndpoint family (OS/DSS/DFS/PFS/MFS) or raw endpoint token (OS/DSS/DFS/RFS/PFS/MFS/DFI/PFI/DRFS/EFS ...). The family is resolved to the concrete token per cohort (see endpoint_resolve()) and recorded in per_dataset$endpoint.
method"REML" (default, iterative restricted maximum likelihood for tau²), "DL" (DerSimonian-Laird, the previous default, kept for continuity), "HK" (Hartung-Knapp-Sidik-Jonkman adjusted variance of the pooled estimate, with its characteristically wider interval) or "FE" (fixed effect). "RE" is still accepted as a synonym of "DL".
pi_methodConstruction rule of the 95% prediction interval for a new cohort: "t" (default, the documented t(k-2) interval on the pooled SE and tau²; needs at least 3 cohorts), "normal" (the normal approximation; needs at least 2) or "HK" (on the HK-adjusted standard error with t(k-1)). The rule used is recorded in $pooled$pi_method and the other construction is returned beside it in $pooled$pi_alt_lower/pi_alt_upper. Only the interval changes: the pooled HR, its confidence interval and the heterogeneity statistics are identical whatever pi_method is.
confoundersOptional character vector of multivariable-adjustment covariate names (must exist in the merged data; the per-cohort intersection of available covariates is used).
min_eventsMinimum number of events for a cohort to be included (default 5).
max_tryNumber of retries when data retrieval fails for a cohort (to absorb API jitter).
mergedOptional named list (cohort name -> already merged data.frame). When supplied, no network retrieval is performed.
pooling"family" (default) pools the Exact-equivalent and the Clinically-related cells of the family, which is what makes a cross-token DFS pool possible; "exact" is the strict mode that pools only cells whose class is Exact-equivalent. The mode used and the classes actually pooled are recorded in $pooled$pooling, $per_dataset$pooling_class and $manifest.
overlapWhat to do when cohorts in the request are known to share patients: "warn" (default) proceeds but warns and records the pairs in $pooled$overlap_pairs, "refuse" stops with an actionable error, "dedupe" keeps one member of each overlapping group (the larger cohort, ties by accession sort) and records what it dropped in $excluded and $manifest$overlap_dropped.
auto_repairLogical, default FALSE (the fail-safe). A cohort whose model would need covariates dropped, levels merged or rows excluded is reported as not estimable with its reasons and offending terms in $excluded, and no model is returned for it. TRUE restores the previous repairing behaviour and records every modification in $modifications.
class_tableOptional endpoint-semantics table (the frozen schema of endpoint_semantics()) used instead of the shipped copy.
overlap_tableOptional shared-patient register (the frozen schema of cohort_overlap()) used instead of the shipped copy.

Examples

## Two lung-cancer cohorts, one OS analysis.
m <- cpas_meta(c("TCGA-LUAD", "GSE31210"), marker = "FOXM1", type = "OS")
m$per_dataset[, c("dataset", "endpoint", "pooling_class", "n", "events", "HR")]
m$pooled              # pooled HR (95% CI), Z/p, Q/df/I2/tau2, prediction interval

## Strict mode: only cells whose class is Exact-equivalent.
m2 <- cpas_meta(c("TCGA-LUAD", "GSE31210"), marker = "FOXM1", type = "OS",
                pooling = "exact", overlap = "warn")

cpas_manifest(m)      # what was pooled, what was dropped, and why
loo_meta(m)           # leave-one-out sensitivity
print(m)
4.11 plot_meta_forest

Description

Draws the forest plot of a cpas_meta() result: the per-cohort HR (95% CI) and the pooled HR. Per-cohort significance stars and the pooled HR / 95% PI annotation are anchored inside the panel, so they are never silently dropped.

Usage

plot_meta_forest(
  x,
  digits = 4,
  show_stars = TRUE,
  label_size = 4.2,
  star_size = NULL,
  y_headroom = 3.6,
  x_frac = 0.02,
  label_lift = 1,
  label_where = c("inside", "subtitle"),
  ...
)

Arguments

ArgumentDescription
xA cpas_meta object.
digitsDecimal places for the annotations in the figure (default 4).
show_starsWhether to draw per-cohort significance stars at the left edge of the panel (* p<0.05, ** p<0.01, *** p<0.001). Default TRUE.
label_sizeFont size of the pooled HR / 95% PI annotation (default 4.2).
star_sizeFont size of the stars and the Overall label; default 0.85 * label_size.

4.19 batch_diagnostics

Description

Multi-cohort pooling rests on two facts this function makes checkable: cpas_meta() is a two-stage meta-analysis whose stage 1 standardises the marker inside each cohort, so a cohort-wide additive shift of the expression scale cancels and does not enter the pooled estimate; and the pooled Kaplan-Meier of cpas_km_pooled() splits each cohort at its own percentile, so no absolute cross-platform threshold is used. 4.24 endpoint_agreement

Description

Takes a filled rating sheet from endpoint_adjudication() and reports how far the raters agree: per-field raw agreement, Cohen's kappa per field with its Landis-and-Koch interpretation, the overall pooled agreement, the adjudication rate and the records whose raters disagreed. Kappa is computed from the nominal contingency table of the two raters, using only rater pairs in which both ratings are present and non-empty, so missing ratings reduce the compared count instead of biasing the estimate; a field in which every rating is the same single category reports kappa = NA rather than NaN. With more than two raters every pair is scored and the field's kappa is the mean of the pairwise Cohen's kappas, which is stated in kappa_basis. This is tooling for running an endpoint-adjudication exercise; running it is not itself a validation study (see section 7).

Usage

Arguments

fieldsJudgement fields to score (default: the five the sheet prepares - event_definition, time_origin, censoring_rule, competing_events, pooling_class).

6. Data Sources & API

CanPAS is built on a curated catalog of 197 cohorts covering 29 cancer types and 38,981 analysable samples, assembled from five source buckets - GEO, EMBL-EBI ArrayExpress / BioStudies, TCGA, CGGA and cBioPortal-hosted studies:

Source archiveCohorts
GEO145
EMBL-EBI (ArrayExpress / BioStudies)14
TCGA33
CGGA3
cBioPortal-hosted2

Cohort-by-family coverage is OS 142, DSS 41, DFS 98, PFS 49 and MFS 17. Every delivered cohort comes with an expression table and a harmonised survival table (time in years, status 0/1), plus clinical covariates where available. TCGA cohorts are the exception on the expression side: the mirror holds no TCGA expression table, so TCGA expression is fetched on demand from UCSC Xena, with the clinical tables held locally.

Each of the 985 cohort-by-family cells carries a semantic record - the token, its role, the event definition, the time origin, the censoring rule, competing events, the source field it was read from, whether it is derived, and the evidence text - together with a pooling class. 347 cells are resolved at token level (endpoint_semantics()); the other cells are families the cohort does not report (Absent, which is the absence of an endpoint and not a pooling verdict). The class splits those 347 into Exact-equivalent and Clinically-related cells, is readable per cell with endpoint_pooling_class(accession, family), and is what cpas_meta(pooling = "exact") filters on. Groups of cohorts known to share patients are recorded in the shared-patient register (30 pairs in this release) and consulted by cpas_meta() through its overlap argument.

Non-TCGA cohorts are served from the public data API / mirror at https://www.jingege.wang/bioinformatics/CPAS/api.php, which the package queries through get_data(). The API is rate-limited and answers repeated queries from the local file cache by default.

Endpoint tokens are harmonised to pooling families: RFS, DFI and EFS are treated as DFS, PFI as PFS, DRFS as MFS, and CSS / BCSS as DSS, so cohorts that report different tokens can be pooled within a family.

7. Verification & Reproducibility

The catalog is produced by a scripted curation pipeline of 67 numbered steps, from series parsing through survival-table construction, clinical standardisation and expression-scale harmonisation. Each step is numbered and rerunnable, so a cohort can be rebuilt from its source series rather than edited by hand. The pipeline now ships inside the package as nine consolidated script files under inst/pipeline/ (01 ingest/parse through 09 analysis and figures) plus the run_pipeline.R entry point - scripts only, no data. cpas_pipeline_steps() lists every step with its original script name, what it does and which consolidated file provides it; cpas_reproducibility_index() indexes the material behind the reported numbers (the curation steps, the exclusion register, the repair and defect records, the frozen state and the additional-file layout).

A verification script cross-checks every catalogued cohort against the data mirror. At the released 197-cohort state it runs 15 checks and reports 0 errors / 0 warnings, with every catalogued row fully usable.

The released package itself installs and checks cleanly: R CMD check reports 0 errors, 0 warnings and 1 note (a host library notice on the check machine). The test suite cross-checks the numerical results against independent reference implementations (survival, metafor, cmprsk).

A reproducibility bundle of the curation scripts and a frozen catalog accompany the release, so the delivered cohort tables can be regenerated and the reported counts re-derived. Every analysis result additionally carries an analysis manifest (cpas_manifest()) recording the cohorts, the resolved token of each, the pooling classes pooled, the selection rule, the rows and covariates dropped and why, the cut-point rule and the number of cut-points searched, the proportional-hazards test, the meta-analysis method, tau², I², the prediction intervals and the R and package versions, so a reported number can be traced back to the run that produced it.

endpoint_adjudication() and endpoint_agreement() generate blinded rating sheets and compute per-field raw agreement, Cohen's kappa with its Landis-and-Koch interpretation, the adjudication rate and the disagreeing records. These are tools for running an endpoint-adjudication exercise: the agreement figures obtained so far come from ratings produced by AI agents by design, not from independent human experts, and no human expert validation study has been carried out. The package also has a public issue tracker at github.com/WangJin93/CanPAS/issues.
